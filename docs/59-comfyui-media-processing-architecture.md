# 59 — NIP media-processing boundary: optional local ComfyUI worker

**Status:** Accepted design amendment on 2026-11-16. This record supersedes only the ASR execution-host detail in [Decision 2](./58-narrative-intelligence-phase-0-decisions.md). It does not change the requirements for feed-specific approval, local audio/transcript processing, source-linked provenance, transcript retention, RIGA model selection, or NIP-specific consent before remote LLM processing. No ComfyUI instance, ASR custom node, model weights, NIP adapter, feed, or provider has been configured or runtime-tested by this decision.

## Decision

NIP may delegate computational media transforms—including local speech recognition and later approved audio/video transforms—to a **local ComfyUI worker** through a typed NIP `AsrProvider`/media-worker port. The first workflow candidate is the optional Qwen3-ASR graph added in the separate `haymant/comfyui-flows` repository. The workflow defaults to Qwen3-ASR 0.6B, automatic language detection, and no timestamps. The Qwen custom-node project reports 0.6B/1.7B model choices, optional forced alignment, and its own dependency requirements; the model card describes 30 languages plus 22 Chinese dialects and identifies the 0.6B weights as Apache-2.0. These are upstream claims, not NIP quality or platform-compatibility acceptance results.

**Do not move all media-related product behavior into ComfyUI.** ComfyUI owns execution of a selected local graph and its inference/transformation outputs. NIP remains the authority for source review and user approval, RSS discovery, feed scheduling, enclosure download policy, per-episode retry/state, audio-size and codec validation, source identity, transcript validation, the canonical DuckDB ledger, source terms, retention/deletion decisions, provenance, and the user-visible audit trail. NIP—not the workflow—decides whether an episode is eligible for processing. A media model or graph never grants rights to fetch or retain its input.

ComfyUI is an optional backend, not a hard dependency on NIP's data model or service. Keep the typed provider port capable of a fake provider for tests and another local implementation if a later decision needs one. If the configured local ComfyUI worker or required node/model is unavailable, NIP reports transcription as unavailable/pending and keeps a retryable episode state. It must not silently send audio to a cloud ASR service or choose a remote Comfy deployment. Claim extraction remains a separate stage that follows the RIGA-selected model; NIP-specific consent is still required before a remote RIGA model receives transcript content.

## Locality, handoff and cleanup

The initial ComfyUI adapter is restricted to a user-selected **loopback HTTP endpoint** (`127.0.0.1`, `::1`, or `localhost`) configured as `NIP_COMFYUI_URL`. Reject non-loopback hosts, redirects to non-loopback destinations, credentials embedded in URLs, and endpoints that resolve to a remote address. ComfyUI's self-hosted raw server API has no compatibility guarantee and may be unauthenticated; its official API-proxy documentation also defaults to loopback and warns that exposing it requires authentication. Do not expose the Desktop server or adapter through a public preview, tunnel, browser URL, or unauthenticated LAN bind. Pin and smoke-test supported ComfyUI/node versions before shipping the adapter.

The NIP adapter stages only an already-approved, size-checked temporary audio file under a NIP-owned per-job directory that ComfyUI can read. It submits a fixed/versioned workflow rather than arbitrary user-provided graphs, obtains transcript text, detected language and any requested timing data, validates the result, and writes the transcript through the NIP store. Feed URLs, source-rights records, database paths and credentials are not passed to ComfyUI. The durable transcript, episode identity and ingestion status are not stored in ComfyUI's history as authoritative state.

Transient audio cleanup covers the NIP job directory and the ComfyUI input/output/history locations touched by the run, including failure, timeout, cancellation and restart recovery. Do not report successful purge until tests prove those files and content-bearing history entries are removed. If the installed ComfyUI version cannot reliably clean its job history, isolate the worker's directories and implement a documented cleanup/reconciliation operation before production integration. Keep model weights/cache separate: users may pre-provision them for offline runs, or choose to download model weights from the documented source. Downloading weights is distinct from uploading episode audio.

For every successful or failed worker run, record a NIP run ID plus workflow hash/version, ComfyUI version, custom-node repository revision, model ID/revision, device/precision, language mode, timestamp setting, start/end time and terminal status. Do not record raw audio or transcript text in diagnostic logs. A final accepted transcript and its content hash are stored by NIP only under the approved source-retention policy.

## Companion workflow repository

`rehab-video-maker` declares `modules/comfy` as a Git submodule pointing to `https://github.com/haymant/comfyui-flows.git` in its [`.gitmodules` file](https://raw.githubusercontent.com/rehabvid/rehab-video-maker/main/.gitmodules). The companion `comfyui-flows` README describes a self-contained ComfyUI Desktop pack for Apple Silicon, with local server scripts and generative H3/SDXL graphs; its pre-existing purpose was not podcast ingestion or transcription. The new ASR workflow adds a local Qwen graph. As separately requested, the workflow repository is now included in `fina-builder` at `modules/comfy` as a pinned submodule; it is an asset/workflow dependency only, not a Rust runtime dependency or NIP adapter.

The companion is pinned as a submodule at `modules/comfy`. NIP integration still requires a typed local API adapter, runtime compatibility, audio cleanup, licensing and cross-platform support review. Keep the ASR node dependency optional so existing image/video workflows do not require its PyTorch/Transformers stack.

## Acceptance gates before NIP calls ComfyUI

1. Build a typed `AsrProvider` port and fake implementation first. The feed/RSS/store path and normal test suite remain runnable without ComfyUI or downloaded models.
2. Add `NIP_COMFYUI_URL` configuration with strict loopback parsing and sanitized diagnostics. Health and capability checks must distinguish worker reachable, required node missing, model absent, unsupported runtime, busy, and worker unavailable.
3. Smoke the exact Qwen3-ASR workflow on a short synthetic or rights-cleared fixture with a pre-provisioned 0.6B model. Compare output against a reviewed transcript oracle, verify language/timestamp behavior and supported audio formats, and measure runtime/memory on each supported desktop OS/GPU class. Do not infer Apple Silicon compatibility from a code path that selects MPS or changes dtype; test the full installed stack.
4. Test retry, duplicate job submission, cancellation, timeout, worker restart, malformed/empty result, too-large input, unavailable model, and process crash. Confirm no partial transcript is committed and no source item is duplicated.
5. Prove deletion of staged audio, generated temporary output, and ComfyUI history content after success and all terminal error states. If purge cannot be enforced, block production adapter acceptance.
6. Validate network isolation: the worker receives no source URL and makes no outbound audio request; integration tests block external audio/model services and permit only loopback. Model download is an explicit setup action, never an implicit transcription-time fallback in privacy-sensitive operation.
7. Keep the Playwright user journey on a deterministic fake ASR provider. A ComfyUI model smoke is a separate opt-in integration test, not a dependency of the narrated browser demo.
