# Fina Commentary Video

Operate Fina as an agent-native production system. The agent performs model reasoning when needed; Fina validates, persists, projects, renders, evaluates and tracks evidence. Never describe a persistence tool as though it generated analysis that the caller did not supply.

## Two entries: thesis video, or event explainer

There are two video kinds, and they are not interchangeable:

- **Thesis video (thesis-first, the F4 flow).** Starts from a thesis in the Thesis tab with `thesis_basis: llm_verified_only` and its commentary transcript (written by fina-scraper `write_commentary_transcript`). The transcript — not re-derived claims — is the narration source. The episode re-verifies every evidence span and every backtest ref, shows the ablation (Run A vs Run B + delta) as a first-class panel and as slides, and is gated by the QA gate codes below and the publish gate. See "Thesis-first video" below.
- **Event explainer (the original flow).** Starts from a retained event and its claims, one slide per selected claim. It has no thesis and no backtest, and it can only ever publish as `internal_review_only` / explainer — never as a thesis video. The 10-step workflow below is the explainer flow; the thesis flow follows the same tool sequence with the thesis-first amendments in each step.

A thesis video states a falsifiable thesis, shows the evidence that supports it, shows the backtest that tested it (including the ablation delta), and states what would invalidate it. A citation collage cannot be disagreed with; a thesis video can be disagreed with for a reason (weak evidence, zero delta, invalidation already happened).

## Thesis-first video

Implemented in the Video Workspace (`src/features/video/thesis.ts`, `VideoWorkspace.tsx`); teach this flow, not the revamp spec:

1. **Entry — "Start from a thesis".** Choose a thesis from the Thesis tab (see the `fina-thesis-review` skill for how a thesis gets there). Choosing it loads its transcript (`_transcripts/<thesis_id>.md|.json`, via `list_transcripts` / `get_transcript` on the fina-scraper side, mirrored into fina-builder) and pre-fills the project: title from the thesis, `as_of` from the thesis, disclosure from the thesis basis. `VideoEpisode.origin` is `'thesis'`; `thesis_id`, `transcript_id` and `transcript_hash` are pinned on the episode. Starting from an event still exists but is labelled "Event explainer (no thesis, no backtest)".
2. **Thesis + evidence re-verification (step 1).** Before storyboarding, every evidence span is re-verified against the retained event text at its Unicode offsets (the same check `exactClaimEvidenceForEvent` does), every backtest ref named by a transcript beat is resolved against a recorded backtest-evidence row, and the episode's pinned transcript hash is re-checked against the loaded transcript. A beat whose span no longer verifies, or whose backtest ref is missing, blocks the episode with the exact failing ref — it is never silently dropped. A provisional thesis blocks here (`thesis_provisional`).
3. **Backtest panel (step 2).** The ablation is a first-class section of the episode: Run A vs Run B table (IC/ICIR, Sharpe, return, max drawdown, feature importances, run_ids, config fingerprints), the out-of-sample delta, and the plain-language verdict ("B beat A out-of-sample by +0.8 Sharpe" or "B did not beat A — thesis not supported"). If the ablation could not run, the panel states exactly why (`could_not_run` + reason) and the episode can proceed only as an explainer, with the absence explicitly recorded and acknowledged — never as a thesis video claiming a delta.
4. **Storyboard — thesis-shaped, 8 beats (step 3).** Built by `buildThesisStoryboard(transcript, thesis, backtest, project, episode)` from the transcript beats in beat order (not claim-list order); narration is the transcript's spoken text, not regenerated from claims. Every slide keeps its transcript beat's claim refs **and** one direct `event` ref per parent source event; every backtest slide keeps its `backtest_id` + `run_id` refs (`evidence_kind: 'backtest'`). No slide without an evidence ref.

   | # | Beat | Visual | Narration source |
   |---|---|---|---|
   | 1 | Hook + thesis | kinetic_text: the thesis in one sentence | transcript beat 1 |
   | 2 | What changed | chart_transition: sentiment trend / burst (z-score, `n`) | transcript beat 2 (or summary) |
   | 3–5 | Evidence (max 3 claims) | evidence_card / quote_card per claim, with exact span | transcript beats, claim + event refs |
   | 6 | The test | evidence_card: Run A vs B table + delta | backtest refs |
   | 7 | What would change my mind | kinetic_text: invalidation condition | thesis invalidation |
   | 8 | Caveat + disclosure | caption: basis, `as_of`, "not investment advice" | thesis metadata |

   The old claim-glue builder (`buildSelectedClaimsStoryboard`, one slide per claim) stays for event explainers, labelled as such. `VideoNarrative.thesis` is the real thesis text (from the transcript), `analysis_mode: 'thesis_backtest'`, with `thesis_id`, `thesis_basis`, `as_of`, `backtest_ids` and `transcript_hash` recorded; `VideoStoryboardDocument` carries `thesis_id`, `backtest_refs` and `source_transcript_hash`.
5. **Render (step 4).** Unchanged: `render_video_linkzag` (Flash/Full), optional Qwen3-TTS per audio cue, job poll, MP4 preview with hash + lineage. One added check: before rendering, read back every pinned VisualSpec and confirm its event refs match the verified receipt event IDs **and** its backtest refs match recorded backtest_ids.
6. **QA + visual review (step 5).** The episode workspace runs `fina_video_qa_run` for the timeline + profile, polls, and shows the report (`VideoQaReport`: status, findings by severity). Zero blockers + zero required checks not run is required before export. QA does not replace manual visual review — the UI shows both separately: "Native QA: passed" and "Visual review: pending / done (by <user>)". QA passes only when the report's `execution_state` is `complete` and its decision is `allow` or `allow_with_warnings`.
7. **Timeline + export (step 6).** `fina_video_timeline_build` (exact refs, `gap_policy: "block"`, unique request id) → readback → `fina_video_export_preflight` → `fina_video_export_start` → manifest readback (`fina_video_export_get`). The timeline and the export manifest (files, hashes, lineage) are reviewable records.
8. **Publish — human approval only (step 7).** The Publish action is disabled unless **all** of these hold: thesis basis is `llm_verified_only`; verification has zero blockers; deterministic QA passed; visual review marked done by a human; export manifest exists; backtest delta is shown (or its absence is explicitly recorded **and** acknowledged by a human); human publish approval is checked. Publishing records who approved, when, and the exact revisions (thesis, transcript hash, storyboard revision, QA report id, export manifest id) — the production receipt. No auto-publish, no publish-from-a-provisional-thesis, ever. An event explainer publishes only as `internal_review_only` / explainer.

### QA gate codes (thesis/backtest)

These are the finding codes `verifyThesisForVideo` / `verifyTranscriptHash` (`src/features/video/thesis.ts`) emit; a thesis video is blocked while any blocker remains. Do not invent other codes, and do not treat an advisory as a pass:

- `thesis_provisional` (blocker) — thesis basis is not `llm_verified_only`. Deep-dive and re-verify; a provisional thesis can never enter a thesis video.
- `thesis_claim_missing` (blocker) — the thesis cites a claim id that is not in the retained claim list.
- `thesis_claim_not_llm_verified` (blocker) — a cited claim is not `tier2_llm` with `review_status` `llm_verified` or `llm_corrected`.
- `span_unverified` (blocker) — a claim's evidence span no longer exactly matches the retained event text at its recorded Unicode offsets, or its event is not loaded.
- `backtest_ref_missing` (blocker) — a transcript beat cites a `backtest_id` with no recorded backtest-evidence row.
- `backtest_delta_absent` (blocker) — no ablation is recorded, or the recorded ablation is marked supported but shows no out-of-sample delta (all delta fields null).
- `backtest_not_supported` (blocker) — the ablation ran and Run B did not beat Run A out-of-sample; the thesis cannot advance to a thesis video.
- `backtest_could_not_run` (advisory) — the ablation could not run (reason recorded); the video may proceed only with the absence explicitly recorded and acknowledged, claiming no delta.
- `invalidation_missing` (blocker) — the thesis states no invalidation condition.
- `transcript_missing` (blocker) — no commentary transcript is recorded for the thesis, or the loaded transcript belongs to a different thesis. A thesis video starts from a transcript, not from claims.
- `transcript_hash_mismatch` (blocker) — the loaded transcript's hash does not match the episode's pinned hash; the transcript changed since the episode started.

## Production workflow

1. **Select a real source.** Prefer a current episode with a publisher-provided transcript. Verify show, episode and date; substantiate any trend/chart statement at its source and record the observation date. Treat “trending” as a dated chart observation, not an audience-size claim.
2. **Import and retain the source.** Use `import_local_event` with its exact schema, then `get_event`. Preserve the returned event ID, content hash, URL and transcript text. Public availability is not a license; record the actual rights statement and user authorization, and do not imply publication clearance.
   **Thesis path:** also import the thesis's primary source events. The transcript's `fina_import_path` (from fina-scraper `export_narrative_for_fina`) is the input to `build_agent_narrative_graph`, with `narrative_thesis` = the real thesis (not a disclaimer) and claims = tier-2-only with exact quotes. The thesis arrives with the transcript; do not re-derive it.
3. **Generate real analysis — or verify the thesis that arrived.** Read the retained transcript and, where needed, cross-check claims with a primary source. Have the external agent or configured model produce the narrative, claim and entity-candidate payload. `build_agent_narrative_graph` validates and persists that payload; it does not call an LLM. Read it back with `list_agent_narrative_analyses` and `list_narrative_graph`. Attribute claims to the speaker/source; preserve number, unit, period, baseline and uncertainty. Treat entity candidates as unresolved, not canonical identities.
   **Thesis path:** the agent does **not** re-derive the thesis from the transcript. Its job is to verify it: re-check every evidence span against the retained event text, check corroboration, read back every backtest ref against its recorded backtest-evidence row, and write the storyboard beats from the transcript beats. If verification fails, the episode is blocked with the exact failing ref (see the QA gate codes above) — never silently drop the beat.
4. **Create a thesis-led native plan (thesis video) or a claim-led native plan (explainer).** Persist the Fina project, episode, evidence links, narrative, storyboard, scenes, shots and visual specs. Use source-span evidence at the narrowest practical scope. Fina’s richer storyboard is canonical; `fina-slides-v1` is only a lossy UI/export projection, never the final video model.
   For every factual beat, keep the exact claim ref and add one direct `event` ref for each parent source event to that same VisualSpec, e.g. `{source_kind: "event", source_id: receipt.event_id, source_revision: null, start_offset: null, end_offset: null, quote: null}`. Keep exact offsets and quotes on the claim evidence refs. Do not rely on claim→event ancestry alone: LinkZag propagates source lineage only from canonical sources named by the pinned VisualSpecs.
   **Thesis video:** the plan is thesis-led — the 8-beat table above, in transcript-beat order, narration taken from the transcript beats. Add one `backtest` ref per backtest slide to the same VisualSpec (`{source_kind: "backtest", source_id: <backtest_id>, ...}`), resolved against a recorded backtest-evidence row; add a `thesis` ref for the thesis itself. `VideoNarrative.thesis` is the real thesis text, `analysis_mode: 'thesis_backtest'`, with `thesis_id`, `thesis_basis`, `as_of`, `backtest_ids` and `transcript_hash`.
5. **Register narration as media and a cue.** Register the exact generated bytes as a `VideoAsset` (`asset_kind: "audio"`) with measured SHA-256, duration, sample count/rate, channels and honest provider/reproducibility metadata. If deterministic mastering is applied, preserve the source asset, register the processed bytes as a separate asset, add an `asset` lineage edge with the exact input hash and record the tool/filter in production metadata; never overwrite the source. Point the cue at the exact processed asset revision and retain the verbatim script, matching script hash, voice/provider metadata, measured audio facts and exact evidence spans. Read it back with `get_video_audio_cue` or `list_video_audio_cues`. Do not invent word-level timing. A cue cannot approve rights.
6. **Render visuals and verify lineage.** Call `render_video_linkzag` with exact persisted VisualSpec revisions; poll `video_job_status` to a terminal state. Verify the output asset’s file hash/probe and `list_video_asset_lineage` ancestors. Check that the renderer preserves visible quote text, attribution and safe margins.
   Before rendering, read back every pinned VisualSpec and confirm its event refs match the verified receipt event IDs. After rendering, require direct event and used-claim edges on the asset. **Thesis video:** also confirm every backtest ref matches a recorded backtest_id before rendering. For an existing asset with a missing event edge, call the official `link_video_asset_lineage` tool only after rechecking the event hash, receipt `event_id`, and every used claim’s exact quote at its recorded Unicode offsets; make the repair idempotent and record the verification. Never edit lineage directly in the database.
7. **Build and read the native EDL.** Call `fina_video_timeline_build` with exact project, episode and storyboard refs, the installed preview profile ID, selected scene/shot/asset evidence refs, audio cue/asset refs, tracks, `gap_policy: "block"` and a unique request ID. The tool does not accept caller paths or FFmpeg fragments. Require `status: "ready"`; then read the exact immutable revision with `fina_video_timeline_get` (or list it) and retain its hash. A blocked build is not a timeline.
   Put exact claim refs in caller-supplied clip/audio `evidence_refs`. Fina merges selected cue evidence into the EDL only after validating event start/end offsets and the exact retained-text quote. Keep lineage-only event refs with null offsets on the VisualSpec/rendered asset, not in caller-supplied EDL evidence.
8. **Run deterministic QA.** Call `fina_video_qa_run` for the exact timeline and matching profile with a unique request ID. Poll its durable job using `video_job_status`, then read the evaluator-produced report with `fina_video_qa_get`. Require `execution_state: "complete"`, zero blockers and zero required checks not run before export. Inspect evidence-span, media byte/hash/probe/decode, rights and lineage findings. Never author, edit or substitute a QA report.
   **Thesis video:** the QA section in the episode workspace runs this and shows the report; the thesis/backtest gate codes above (`thesis_provisional`, `backtest_ref_missing`, `backtest_delta_absent`, `span_unverified`, `invalidation_missing`, `transcript_missing`, `transcript_hash_mismatch`, …) are blockers, and `backtest_could_not_run` is an advisory that still needs explicit human acknowledgement of the missing delta. QA does not replace manual visual review — report both separately.
9. **Preflight and export.** Discover the installed preview profile using `fina_video_export_profiles_list`; call read-only `fina_video_export_preflight` with the exact timeline and persisted QA refs. Start `fina_video_export_start` only when preflight authorizes it. Poll its durable job, require success, then read the immutable producer manifest with `fina_video_export_get` and verify the listed asset and lineage. Do not manually mux a final file or fabricate an export manifest.
10. **Verify and report.** Independently check the delivered file hash, size, container, codecs, dimensions, frame rate, duration and audio streams with `ffprobe`; decode it and inspect representative frames/contact sheet. Deterministic QA does not replace manual visual review. Distinguish completed native QA/export from pending visual review. Keep internal-review-only outputs private; this state is not publication rights clearance.

## Evidence and rights rules

- Use `extract_claims_from_event` only when a configured RIGA provider and required consent workflow are available. Do not use fixture extraction tools or invented transcript objects.
- External analysis quotes must exactly match the retained event text. Preserve verified Unicode-character offsets and quotes; Fina validates supplied spans against retained event or claim evidence and rejects missing, partial, altered or out-of-range citations.
- User-confirmed local analysis/commentary authorization, a ready media capability and `internal_review_only` status do not establish public distribution rights. A preview QA warning is not a legal review or clearance.
- If analysis, evidence, media integrity, required QA, or rights checks are missing or blocked, stop at the last verified artifact and report the exact gap. Never label manual checks as native QA.

## Tool sequence

Thesis video: thesis (Thesis tab, `llm_verified_only`) → transcript (`list_transcripts` / `get_transcript`) → re-verification (spans, backtest refs, transcript hash) → `import_local_event` → `get_event` → `export_narrative_for_fina` → `build_agent_narrative_graph` → analysis/graph readback → native project and storyboard records (8-beat thesis storyboard) → `register_video_asset` and `register_video_audio_cue` → `render_video_linkzag` → `video_job_status`/lineage readback → `fina_video_timeline_build` → timeline readback → `fina_video_qa_run` → job poll → `fina_video_qa_get` → `fina_video_export_profiles_list` → `fina_video_export_preflight` → `fina_video_export_start` → job poll → `fina_video_export_get`/asset and lineage readback → independent playback and visual review → publish gate (human approval only).

Event explainer: `import_local_event` → `get_event` → external-agent/model analysis → `build_agent_narrative_graph` → analysis/graph readback → native project and storyboard records → `register_video_asset` and `register_video_audio_cue` → `render_video_linkzag` → `video_job_status`/lineage readback → `fina_video_timeline_build` → timeline readback → `fina_video_qa_run` → job poll → `fina_video_qa_get` → `fina_video_export_profiles_list` → `fina_video_export_preflight` → `fina_video_export_start` → job poll → `fina_video_export_get`/asset and lineage readback → independent playback and visual review → publish only as `internal_review_only` / explainer.

Verify tool names and schemas with `tools/list` before execution because capabilities evolve. Keep the job output, immutable refs, hashes, QA decision, export manifest and visual-review status together as the production receipt.

## Recommended narrative shape

Build around one defensible tension, supported by two to five attributed claims. Distinguish reported fact, company guidance, forecast, interpretation and risk. Keep transcript evidence separate from external corroboration. Make conclusions bounded interpretations, not investment advice.

For a thesis video this shape is the storyboard's 8-beat table above — the UI implements it, with the backtest as beat 6 and the invalidation as beat 7. A thesis video's conclusion is a bounded interpretation of the thesis + the ablation delta, never a trade instruction.
