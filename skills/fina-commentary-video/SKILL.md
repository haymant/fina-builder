# Fina Commentary Video

Operate Fina as an agent-native production system. The agent performs model reasoning when needed; Fina validates, persists, projects, renders, evaluates and tracks evidence. Never describe a persistence tool as though it generated analysis that the caller did not supply.

## Production workflow

1. **Select a real source.** Prefer a current episode with a publisher-provided transcript. Verify show, episode and date; substantiate any trend/chart statement at its source and record the observation date. Treat “trending” as a dated chart observation, not an audience-size claim.
2. **Import and retain the source.** Use `import_local_event` with its exact schema, then `get_event`. Preserve the returned event ID, content hash, URL and transcript text. Public availability is not a license; record the actual rights statement and user authorization, and do not imply publication clearance.
3. **Generate real analysis.** Read the retained transcript and, where needed, cross-check claims with a primary source. Have the external agent or configured model produce the narrative, claim and entity-candidate payload. `build_agent_narrative_graph` validates and persists that payload; it does not call an LLM. Read it back with `list_agent_narrative_analyses` and `list_narrative_graph`. Attribute claims to the speaker/source; preserve number, unit, period, baseline and uncertainty. Treat entity candidates as unresolved, not canonical identities.
4. **Create a claim-led native plan.** Persist the Fina project, episode, evidence links, narrative, storyboard, scenes, shots and visual specs. Use source-span evidence at the narrowest practical scope. Fina’s richer storyboard is canonical; `fina-slides-v1` is only a lossy UI/export projection, never the final video model.
   For every factual beat, keep the exact claim ref and add one direct `event` ref for each parent source event to that same VisualSpec, e.g. `{source_kind: "event", source_id: receipt.event_id, source_revision: null, start_offset: null, end_offset: null, quote: null}`. Keep exact offsets and quotes on the claim evidence refs. Do not rely on claim→event ancestry alone: LinkZag propagates source lineage only from canonical sources named by the pinned VisualSpecs.
5. **Register narration as media and a cue.** Register the exact generated bytes as a `VideoAsset` (`asset_kind: "audio"`) with measured SHA-256, duration, sample count/rate, channels and honest provider/reproducibility metadata. If deterministic mastering is applied, preserve the source asset, register the processed bytes as a separate asset, add an `asset` lineage edge with the exact input hash and record the tool/filter in production metadata; never overwrite the source. Point the cue at the exact processed asset revision and retain the verbatim script, matching script hash, voice/provider metadata, measured audio facts and exact evidence spans. Read it back with `get_video_audio_cue` or `list_video_audio_cues`. Do not invent word-level timing. A cue cannot approve rights.
6. **Render visuals and verify lineage.** Call `render_video_linkzag` with exact persisted VisualSpec revisions; poll `video_job_status` to a terminal state. Verify the output asset’s file hash/probe and `list_video_asset_lineage` ancestors. Check that the renderer preserves visible quote text, attribution and safe margins.
   Before rendering, read back every pinned VisualSpec and confirm its event refs match the verified receipt event IDs. After rendering, require direct event and used-claim edges on the asset. For an existing asset with a missing event edge, call the official `link_video_asset_lineage` tool only after rechecking the event hash, receipt `event_id`, and every used claim’s exact quote at its recorded Unicode offsets; make the repair idempotent and record the verification. Never edit lineage directly in the database.
7. **Build and read the native EDL.** Call `fina_video_timeline_build` with exact project, episode and storyboard refs, the installed preview profile ID, selected scene/shot/asset evidence refs, audio cue/asset refs, tracks, `gap_policy: "block"` and a unique request ID. The tool does not accept caller paths or FFmpeg fragments. Require `status: "ready"`; then read the exact immutable revision with `fina_video_timeline_get` (or list it) and retain its hash. A blocked build is not a timeline.
   Put exact claim refs in caller-supplied clip/audio `evidence_refs`. Fina merges selected cue evidence into the EDL only after validating event start/end offsets and the exact retained-text quote. Keep lineage-only event refs with null offsets on the VisualSpec/rendered asset, not in caller-supplied EDL evidence.
8. **Run deterministic QA.** Call `fina_video_qa_run` for the exact timeline and matching profile with a unique request ID. Poll its durable job using `video_job_status`, then read the evaluator-produced report with `fina_video_qa_get`. Require `execution_state: "complete"`, zero blockers and zero required checks not run before export. Inspect evidence-span, media byte/hash/probe/decode, rights and lineage findings. Never author, edit or substitute a QA report.
9. **Preflight and export.** Discover the installed preview profile using `fina_video_export_profiles_list`; call read-only `fina_video_export_preflight` with the exact timeline and persisted QA refs. Start `fina_video_export_start` only when preflight authorizes it. Poll its durable job, require success, then read the immutable producer manifest with `fina_video_export_get` and verify the listed asset and lineage. Do not manually mux a final file or fabricate an export manifest.
10. **Verify and report.** Independently check the delivered file hash, size, container, codecs, dimensions, frame rate, duration and audio streams with `ffprobe`; decode it and inspect representative frames/contact sheet. Deterministic QA does not replace manual visual review. Distinguish completed native QA/export from pending visual review. Keep internal-review-only outputs private; this state is not publication rights clearance.

## Evidence and rights rules

- Use `extract_claims_from_event` only when a configured RIGA provider and required consent workflow are available. Do not use fixture extraction tools or invented transcript objects.
- External analysis quotes must exactly match the retained event text. Preserve verified Unicode-character offsets and quotes; Fina validates supplied spans against retained event or claim evidence and rejects missing, partial, altered or out-of-range citations.
- User-confirmed local analysis/commentary authorization, a ready media capability and `internal_review_only` status do not establish public distribution rights. A preview QA warning is not a legal review or clearance.
- If analysis, evidence, media integrity, required QA, or rights checks are missing or blocked, stop at the last verified artifact and report the exact gap. Never label manual checks as native QA.

## Tool sequence

`import_local_event` → `get_event` → external-agent/model analysis → `build_agent_narrative_graph` → analysis/graph readback → native project and storyboard records → `register_video_asset` and `register_video_audio_cue` → `render_video_linkzag` → `video_job_status`/lineage readback → `fina_video_timeline_build` → timeline readback → `fina_video_qa_run` → job poll → `fina_video_qa_get` → `fina_video_export_profiles_list` → `fina_video_export_preflight` → `fina_video_export_start` → job poll → `fina_video_export_get`/asset and lineage readback → independent playback and visual review.

Verify tool names and schemas with `tools/list` before execution because capabilities evolve. Keep the job output, immutable refs, hashes, QA decision, export manifest and visual-review status together as the production receipt.

## Recommended narrative shape

Build around one defensible tension, supported by two to five attributed claims. Distinguish reported fact, company guidance, forecast, interpretation and risk. Keep transcript evidence separate from external corroboration. Make conclusions bounded interpretations, not investment advice.
